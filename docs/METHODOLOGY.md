# Research methodology

*Written to be adaptable as the methodology chapter of a postgraduate capstone dissertation.
Numerical findings are reported separately in `docs/RESULTS.md`, generated from executed runs.*

## 1. Problem statement

Generative models make it cheap to produce fluent text at scale. Two technical responses are commonly
proposed for establishing where a piece of text came from:

1. **Watermarking** — the generator embeds a statistical signal at sampling time that a key-holder can
   later test for (Kirchenbauer et al., 2023; Zhao et al., 2024).
2. **Post-hoc detection** — a classifier estimates whether text is machine-generated from its surface
   statistics, without any cooperation from the generator (Solaiman et al., 2019; Gehrmann et al., 2019;
   Mitchell et al., 2023; Hans et al., 2024).

Both are used informally as "provenance" evidence, yet they answer different questions and fail in
different ways. MAI-13 measures, under one controlled protocol, how reliable each signal is on clean
text, how quickly it degrades under realistic transformations, and what it costs.

## 2. Research questions

- **RQ1 (detectability).** On held-out text, how well do KGW and Unigram watermarks separate watermarked
  continuations from human and unwatermarked AI continuations, at operationally relevant false-positive
  rates (1%, 5%)?
- **RQ2 (robustness).** How does detection degrade under truncation, word-level edits, typos, formatting
  changes, lexical substitution, back-translation and LLM paraphrasing, and how does that degradation
  relate to how much meaning the attack preserves?
- **RQ3 (baseline comparison).** Does a classifier using language-model statistics outperform a TF-IDF
  baseline at identifying AI text from the same generator, and how do both behave on watermarked and
  attacked text (distribution shift)?
- **RQ4 (cost).** What does watermarking cost in text quality (oracle perplexity, repetition) and in
  generation/detection latency?

## 3. Hypotheses

- H1: Both watermarks achieve AUROC ≥ 0.95 on clean 150–200-token continuations, with test FPR at the
  theoretical threshold z = 4 near 0.
- H2: Unigram is more robust than KGW (h=1) to token-local edits (deletion, substitution), because an
  edit changes the green status of one token for Unigram but of two tokens for KGW.
- H3: Paraphrase and back-translation, which re-sample most tokens, reduce detection substantially for
  both watermarks; the format-level zero-width baseline is unaffected by word edits but fails completely
  under Unicode normalisation.
- H4: The LM-feature classifier outperforms TF-IDF in AUROC (paired), but both degrade under attacks.

## 4. Experimental protocol

### 4.1 Data
- **Source:** C4 `realnewslike` validation split (ODC-BY), streamed and cached with a SHA-256 manifest.
- **Unit:** one document → prompt (first 50 words) and *human continuation* (next 150 words, sliced from
  the original string).
- **AI continuations:** Qwen2.5-0.5B (base) continues each prompt with multinomial sampling
  (temperature 0.8, top-p 0.95, 150–200 new tokens), once without a watermark and once per
  generation-time watermark, using the same seed. The zero-width mark is applied post hoc to the
  unwatermarked AI text.
- **Labels:** human = C4 original; AI = generated by construction. Every label carries a recorded
  justification (`label_source`).

### 4.2 Splits and leakage control
Splits are assigned per **document** (60/20/20 train/val/test) using a seeded hash, and every derived
text inherits its document's split. Two leakage audits are run: on source texts at build time and on
all generated/derived texts after generation (exact normalised-hash matches and MinHash/LSH near
duplicates at Jaccard ≥ 0.8 across splits, plus groups spanning splits).

### 4.3 Watermark configuration
- KGW: γ = 0.25, δ = 2.0, context width h = 1, unique (context, token) scoring.
- Unigram: γ = 0.25, δ = 2.0, h = 0.
- Detection: one-proportion z-test; texts with < 16 scorable tokens are *insufficient* and counted as
  not detected.
- Green-list membership is computed with a keyed splitmix64 PRF (see `docs/ARCHITECTURE.md` §5), not
  `torch.randperm`; this is a documented deviation from the reference code that does not change the
  statistical model.

### 4.4 Thresholds
Two threshold rules are reported for every watermark:
1. **Theoretical:** z = 4 (method default, independent of data).
2. **Empirical:** the smallest threshold whose FPR on **validation** negatives (human + unwatermarked AI)
   is ≤ the target (1% and 5%). The threshold is frozen before looking at the test split.

AI-text classifiers use the same empirical rule with validation **human** texts as negatives.

### 4.5 Attacks
Applied to every test-split watermarked text and, separately, to test-split human texts (to measure
false positives under transformation). Seeds are derived from stable identifiers (seed, document,
kind, watermark, attack), so reruns apply identical edits. Expensive attacks (back-translation, LLM
paraphrase) run on a fixed seeded subset of test documents shared across methods (`max_groups`), and
their clean baselines are restricted to the same documents. Attacks that cannot run (e.g. no Gemini key)
are recorded as *skipped* and produce no numbers.

| Attack | Type | Strength |
|---|---|---|
| truncate_50pct / truncate_25words | truncation | keep first 50% / first 25 words |
| delete_10pct / delete_30pct | edit | delete each word w.p. 0.1 / 0.3 |
| swap_10pct | edit | swap adjacent pairs w.p. 0.1 |
| typos_10pct | edit | perturb 10% of words by one character |
| normalize_format | formatting | NFKC + strip format characters + collapse whitespace |
| homoglyphs_10pct | formatting | replace 10% of eligible Latin letters with Cyrillic look-alikes |
| lexical_20pct | edit | replace 20% of words with DistilRoBERTa top-5 suggestions |
| backtranslate_de | translation | MarianMT en→de→en, greedy |
| paraphrase_local / paraphrase_gemini | paraphrase | Qwen2.5-0.5B-Instruct / Gemini, T = 0.7 |

### 4.6 Metrics
| Quantity | Definition | Uncertainty |
|---|---|---|
| AUROC | positives vs negatives on test | stratified percentile bootstrap (1000) |
| TPR, FPR, precision, recall, F1 | at a frozen threshold | Wilson 95% interval for proportions |
| TPR after attack | detected attacked positives / all clean test positives on the attacked documents (failed transformations = not detected) | Wilson |
| Conditional survival | P(detected after attack \| detected before) | Wilson |
| FPR on attacked human text | false positives among transformed human texts | Wilson |
| Δscore | mean paired change in detector score after attack | bootstrap |
| Semantic similarity | cosine of MiniLM sentence embeddings, attacked vs parent | bootstrap |
| Quality | oracle perplexity (GPT-2-medium), 3-gram repetition rate | bootstrap |
| ΔAUROC vs baseline | paired difference on identical test samples | paired stratified bootstrap, two-sided percentile p |
| Cost | generation tokens/s with/without watermark, detection ms/text, stage wall-clock | — |

Subgroups: negatives split into human vs unwatermarked AI; detection rate by number of scored tokens
(length bins); attacked vs clean.

### 4.7 Reproducibility
Each run stores: validated config and its hash, seed, dataset version and records hash, software version,
git commit, Python/torch/transformers/sklearn versions, CPU count and thread count. Generation, splitting,
attacks and bootstraps are seeded; `rerun` re-executes the identical configuration. An automated test
asserts that two runs of the same configuration produce identical generated texts and identical metrics.

## 5. Threats to validity

**Internal.**
- *Implementation fidelity:* the KGW/Unigram implementations follow the papers' equations; they are
  verified by unit tests (z-score formula, γ-fraction, wrong-key negatives, repeated n-gram handling)
  but not by bit-exact comparison with the reference code (the PRF differs by design).
- *Label noise:* C4 may contain machine-generated pages; this would *lower* measured classifier
  performance and could inflate watermark FPR only if such pages happened to be green-biased, which is
  implausible without the key.
- *Confounds in classifier comparison:* human and AI texts differ in length distribution and formatting
  (newlines are rarer in model output); the TF-IDF baseline may exploit these.

**External.**
- One generator (0.5B parameters), one domain (2019 English news-like web text), one language.
  Larger models have lower-entropy outputs, which weakens watermarks for the same δ.
- The local paraphraser is weak; Gemini paraphrase is optional. Results for paraphrase therefore bound
  the attack from below, not above.
- Binoculars with GPT-2-sized models is not representative of the published method's strength.

**Construct.**
- "Detected" means z ≥ threshold for a specific key: it is evidence of key usage, not authorship.
- Semantic similarity via a small embedding model is a proxy for meaning preservation; it is high for
  paraphrases that subtly change facts.

**Statistical conclusion.**
- With ~60 test documents per condition, a 95% interval on a proportion near 0.5 is roughly ±0.12;
  conclusions are drawn only where intervals are clearly separated or the paired test is significant.
- Many comparisons are reported; they are descriptive, and no family-wise correction is applied.

## 6. Ethics and responsible use
Detectors are not to be used for decisions about individuals. The zero-width baseline is included to
demonstrate spoofability, not as a recommendation. All data are public and licensed for research; no
personal data are collected by the platform beyond what appears in C4.
